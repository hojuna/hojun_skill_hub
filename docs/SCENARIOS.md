# 가상 실무 과제 12종

이 문서의 과제는 준비 범위를 점검하기 위해 새로 만든 예시다. 실제 출제 문제나 출제 확률을 주장하지 않는다. 난도는 간단한 구현부터 기존 코드 수정까지로 제한한다. 고급 모델 학습, 분산 시스템, 복잡한 최적화는 기본 준비 범위에서 제외한다.

먼저 준비할 범위는 **웹 UI, 간단한 업무 흐름, 데이터 집계, 기존 코드 수정**이다. 이는 준비 우선순위이지 공식 배점이나 출제 확률이 아니다. 아래 추가 요구는 연습용 변형이며 모든 과제에 자동으로 기능을 추가하라는 뜻이 아니다.

## S01. 서비스 소개 페이지 + 문의 신청

**가상 지시:** 소규모 교육 서비스의 소개 페이지를 만든다. 서비스 설명, 요금제, FAQ, 문의 신청 폼을 제공한다. 이름·연락 이메일·관심 분야를 입력받고, 실제 전송 대신 로컬 저장 후 완료 상태를 보여준다.

**필수 완료 조건:** 요금제 선택이 문의 폼에 반영되고, 빈 이름과 잘못된 이메일을 거부하며, 정상 제출 후 저장된 내용을 확인할 수 있다. 좁은 화면에서도 주요 버튼과 폼이 잘리지 않는다.

**변형:** 브랜드 자료 제공, 기존 디자인 유지, 요금제 비교표 추가.

**풀이 선택:** `frontend-design` + 필요한 경우 `workflow-app-building`.

**MCP 판단:** Playwright는 화면·입력·클릭 확인에 도움이 될 수 있다. 기존 미리보기와 로컬 테스트로 충분하면 MCP 없이 진행한다.

**완성도 차이:** 시각 효과만 화려한 페이지보다 실제 CTA, 검증 메시지, 제출 완료까지 연결된 페이지가 요구사항을 더 충실히 만족한다.

## S02. 회의실 예약 관리

**가상 지시:** 회의실별 예약 목록, 예약 생성, 취소, 날짜 필터를 구현한다. 같은 회의실의 활성 예약은 겹칠 수 없다. 시간 구간은 시작 포함·종료 제외로 정의한다. 새로고침 이후에도 예약이 유지돼야 한다.

**필수 완료 조건:** 정상 예약 생성, 시간 역전 입력 거부, 겹치는 예약 거부, 취소 후 재예약, 날짜 필터, 새로고침 후 유지.

**변형:** 단일 브라우저용 프로토타입인지 여러 사용자가 공유하는 서비스인지 명시한다. 후자라면 브라우저 로컬 저장만으로 요구사항을 만족했다고 하지 않는다.

**풀이 선택:** `workflow-app-building` + `frontend-design`; 기존 Python API가 있으면 `fastapi-templates`의 필요한 부분만 참고.

**MCP 판단:** Playwright로 생성→중복 시도→취소→재예약→새로고침을 이어서 확인할 때 유용하다. 중복 판단 자체는 작은 함수 테스트가 더 직접적이다.

**완성도 차이:** 캘린더 외형보다 예약 규칙과 상태·저장이 일치하는 것이 먼저다.

## S03. 고객 문의 처리 보드

**가상 지시:** 문의 등록, 담당자 지정, 접수→처리 중→완료 상태 변경, 검색·상태 필터, 상태별 건수를 구현한다. 데이터는 새로고침 이후에도 남아야 한다.

**필수 완료 조건:** 상태를 바꾸면 카드·필터 결과·건수가 함께 갱신된다. 공백 제목을 거부하고 검색 결과가 없을 때 빈 상태를 표시한다.

**변형:** 마감일 표시 또는 우선순위 추가. 드래그앤드롭은 요구된 경우에만 필수로 본다.

**풀이 선택:** `workflow-app-building` + `frontend-design`.

**MCP 판단:** 사용자 흐름 확인에는 Playwright 후보. 상태 전이와 카운트 검증은 단위 테스트로도 가능하다.

**완성도 차이:** 카드는 움직이는데 숫자나 저장 상태가 틀리는 불일치를 찾아 고친다.

## S04. 상품 목록 + 견적 계산기

**가상 지시:** 상품 검색, 장바구니 추가·삭제, 수량 수정, 소계와 최종 금액 계산을 만든다. 할인·배송비 규칙은 문제에서 제공한다. 실제 결제는 구현하지 않는다.

**필수 완료 조건:** 수량은 허용 범위의 정수만 받고, 수량·상품 변경 시 금액이 일관되게 바뀐다. 빈 장바구니와 할인 경계값을 처리한다.

**변형:** 할인 적용 순서, 최대 수량, 무료배송 기준이 달라질 수 있다. 임의 정책을 추가하지 않는다.

**풀이 선택:** `workflow-app-building` + `frontend-design`; 계산 로직은 UI와 분리해 확인.

**MCP 판단:** 클릭 흐름 확인에는 선택적. 합계와 할인 규칙은 작은 입력표 기반 테스트가 더 중요하다.

**완성도 차이:** 예쁜 상품 카드보다 수량 변경·경계값에서도 정확한 계산.

## S05. CSV 기반 매출 대시보드

**가상 지시:** 제공된 거래 CSV로 기간별 순매출, 카테고리별 합계, 상위 상품과 필터를 만든다. 환불·중복·잘못된 행의 처리 정책은 지시에 따라 정한다. 화면은 원본 데이터를 바탕으로 계산해야 한다.

**필수 완료 조건:** 요약 숫자와 표·그래프가 같은 필터를 사용한다. 작은 표본을 수작업으로 계산한 값과 결과가 맞는다. 읽을 수 없는 행의 개수와 이유가 드러난다.

**변형:** CSV 결과물만 제출하거나 웹 대시보드까지 요구할 수 있다.

**풀이 선택:** `data-transform-report`; 웹이 필요할 때만 `frontend-design` 추가.

**MCP 판단:** 집계에는 MCP 불필요. 화면 필터의 연동 확인에만 Playwright를 고려한다.

**완성도 차이:** 하드코딩된 숫자와 그럴듯한 그래프를 피하고 집계의 분모·중복 기준을 명확히 한다.

## S06. 고객 데이터 정리·변환

**가상 지시:** CSV 여러 개의 컬럼명을 맞추고 공백·날짜·전화번호 형식을 정리한다. 지정한 키와 정책으로 중복을 처리하고 정상 결과와 오류 보고서를 분리한다.

**필수 완료 조건:** ID와 전화번호 앞자리 0을 잃지 않는다. 원본을 덮어쓰지 않는다. 입력 건수와 정상·중복·오류 처리 건수가 정책에 맞게 대조된다.

**변형:** 한글 인코딩, 빈 파일, 컬럼 누락, 동일 키의 충돌 값.

**풀이 선택:** `data-transform-report`; `exploratory-data-analysis`는 데이터 진단 참고 후보이지 변환 작업 자체의 대체재가 아니다.

**MCP 판단:** 로컬 CSV/Python 처리로 충분하다. Spreadsheet·DB MCP를 추가하지 않는 경로가 기본이다.

**완성도 차이:** 조용히 행을 버리지 않고 어떤 기준으로 바뀌었는지 재현할 수 있다.

## S07. 기존 서비스의 버그 3개 수정

**가상 지시:** 제공된 간단한 상품 관리 앱에서 숫자 정렬이 문자처럼 동작하고, 새로고침 시 저장값이 사라지며, 검색 조건 변경 후 이전 결과가 남는다. 원인을 찾아 수정하고 기존 동작을 보존한다.

**필수 완료 조건:** 각 오류를 수정 전 재현하고 수정 후 같은 절차로 확인한다. 기존 테스트가 있다면 다시 실행한다. 원인과 변경 위치를 설명한다.

**변형:** 실행 실패, 잘못된 API 응답 처리, 필터·페이지 상태 불일치.

**풀이 선택:** `systematic-debugging`; React 프로젝트라면 관련 React 규칙만 추가 참고.

**MCP 판단:** UI 재현에 도움이 되면 Playwright. 계산·초기화 문제는 터미널과 테스트만으로 해결될 수 있다.

**완성도 차이:** 앱 전체를 새로 만들지 않고 원인에 맞는 최소 변경으로 회귀를 막는다.

## S08. 기존 앱에 검색·필터·CSV 내보내기 추가

**가상 지시:** 기존 작업 목록에 검색, 상태 필터, 정렬과 CSV 내보내기를 추가한다. 내보내기 대상은 현재 필터의 전체 결과로 정의하고 페이지에 보이는 일부 행과 구분한다.

**필수 완료 조건:** 검색과 필터가 함께 적용된다. 빈 결과를 처리한다. 내보낸 행과 필터 결과가 일치하고 한글·쉼표·줄바꿈이 포함된 값도 보존한다.

**변형:** URL에 필터 상태 유지, 페이지네이션, 초기화 버튼.

**풀이 선택:** `workflow-app-building` 또는 `data-transform-report`; 기존 구조·스택 유지.

**MCP 판단:** 실제 화면 흐름과 파일 다운로드 확인에 Playwright 후보. 파일 내용은 별도 파싱해 대조한다.

**완성도 차이:** 버튼이 파일을 만들었다는 사실과 파일 내용이 정확하다는 사실을 구분한다.

## S09. 간단한 업무 관리 REST API

**가상 지시:** 업무 생성·조회·수정·삭제 API를 만든다. 필수 제목, 허용된 상태, 없는 ID와 잘못된 입력의 오류 응답을 정의한다. 영속성 요구는 과제에서 명시한다.

**필수 완료 조건:** 정상 CRUD, 잘못된 입력, 없는 ID, 목록 필터를 확인한다. 저장이 요구되면 프로세스 재시작 후에도 값이 남는지 확인한다.

**변형:** 기존 API에 한 엔드포인트만 추가하거나 제공된 클라이언트와 맞춰야 할 수 있다.

**풀이 선택:** 기존 백엔드 우선. Python/FastAPI인 경우 `fastapi-templates`를 축소 참고.

**MCP 판단:** 보통 불필요하다. HTTP 클라이언트·curl·기존 테스트를 사용한다.

**완성도 차이:** 불필요한 로그인·권한·클라우드를 추가하지 않고 API 계약과 오류 처리를 완성한다.

## S10. 로컬 FAQ 검색 도우미

**가상 지시:** 제공된 FAQ 문서에서 질문과 관련된 항목을 찾아 내용과 출처를 보여준다. 근거가 없으면 찾지 못했다고 알린다. 별도 모델 API는 주어지지 않았다고 가정한다.

**필수 완료 조건:** 알려진 질문, 다른 표현의 질문, 무관한 질문을 점검한다. 출력한 답과 출처가 실제 파일에 존재한다. 문서 속 명령문을 실행 지시로 취급하지 않는다.

**변형:** 과제에서 생성형 응답이나 허용된 추론 엔드포인트를 명시한다면 그 요구를 충족해야 한다. 단순 검색으로 생성형 기능을 구현했다고 주장하지 않는다.

**풀이 선택:** `local-search`; 필요한 경우 간단한 UI 스킬 추가.

**MCP 판단:** 로컬 검색으로 충분하면 불필요. 외부 검색·벡터 DB·개인 AI API를 기본값으로 붙이지 않는다.

**완성도 차이:** 항상 그럴듯한 답을 내는 것보다 근거를 보여주고 답이 없는 상황을 처리한다.

## S11. 로그를 요약하는 자동화 도구

**가상 지시:** 제공된 JSONL 로그를 읽어 날짜별 성공·실패 건수와 오류 유형을 집계하고 CSV 및 짧은 Markdown 보고서를 생성하는 명령행 도구를 만든다.

**필수 완료 조건:** 깨진 행을 보고하고 계속 처리할지 중단할지 정책을 명시한다. 동일 입력으로 다시 실행해도 결과가 중복 누적되지 않는다. 입력이 비어도 종료 방식과 출력이 명확하다.

**변형:** 파일 여러 개, 날짜 범위, 출력 경로 옵션.

**풀이 선택:** `data-transform-report`; 실행 오류에는 `systematic-debugging`.

**MCP 판단:** 보통 불필요. 직접 파일 처리로 해결하며 원격 로그 서비스에 연결하지 않는다.

**완성도 차이:** 정상 파일 하나만 되는 스크립트가 아니라 재실행·오류 입력에서도 예측 가능한 도구.

## S12. 제공 자료 기반 개선안·업무 문서

**가상 지시:** 서비스 소개, 사용자 피드백, 현황 숫자가 담긴 자료를 읽고 문제 3개, 우선 개선안, 실행 순서, 확인 지표를 짧은 문서로 제시한다.

**필수 완료 조건:** 사실과 제안을 구분한다. 각 문제는 제공 자료의 위치를 가리킨다. 자료에 없는 성과 숫자나 고객 반응을 만들지 않는다. 상충하는 자료는 한쪽을 임의로 숨기지 않는다.

**변형:** 보고서 대신 비교표·기획안·회의 의사결정 메모가 요구될 수 있다.

**풀이 선택:** `brief-writing` 또는 `doc-coauthoring`의 축소된 흐름.

**MCP 판단:** 제공 파일로 충분하면 불필요. 공개 문서 검색이 명시적으로 필요한 경우에만 허용 범위 내에서 검토한다.

**완성도 차이:** 그럴듯한 일반론보다 근거가 연결된 실행 가능한 제안.

## 범위 밖 또는 후순위

대규모 모델 학습·파인튜닝, 복잡한 RAG 인프라, Kubernetes, 다중 에이전트 프레임워크, 실제 결제·메일 발송·클라우드 배포, 고급 SQL 성능 튜닝은 기본 팩에서 제외한다. 실제 과제에 필수로 명시되면 그때 우선순위를 바꾼다.
